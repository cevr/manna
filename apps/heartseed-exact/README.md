# @manna/heartseed-exact

Heartseed on [Exact](https://github.com/expo/exact), bundle id `app.heartseed.exact`, ported beside `apps/heartseed` until it replaces it. How to install Exact, the pin, the wrapper and the simulators: `docs/exact.md`.

```sh
bun run exact contract build app.contract --json --errors-only   # [] means no errors
bun run exact web            # the dev loop, at http://127.0.0.1:8765/
bun run exact test web       # the contract tests in headless Chrome
bun run exact test ios       # the same on verify-heartseed-exact
bun run exact verify         # tests, checks, a relaunch: done when clean
bun run exact verify ios
bun tools/drive-say.ts web   # Say it on /cue/<cue>: a try, its help and a refusal, driven through the agent (also: ios)
bun tools/drive-session.ts web  # the daily session: Next into the garden, a try left, a run to its end, Minutes (also: ios)
bun tools/drive-look.ts web  # the brand in light and dark, the sheet's choices checked and kept (also: ios)
bun tools/drive-garden.ts web   # the garden: a recall's day, peek, Show all, a relaunch, twenty singles (also: ios)
bun tools/drive-home.ts web  # home: a pressed plant, the buttons' names, Move back, a relaunch (also: ios)
bun tools/drive-join.ts web  # home and the session: a verse said through, then its plant and the card on home (also: ios)
bun tools/drive-add.ts web   # Add verses on a plain launch: a chooser list kept across a relaunch, Psalm 119, one verse through the chooser and twenty single verses, no test control (also: ios)
bun tools/drive-commentary.ts web  # the downloader with the commentary against its fixture: the line, a relaunch, a 304, a new version, each failure and Try again, a plain launch (also: ios)
bun run test                 # the Bun tests the gate runs (no Exact needed), with test:app, test:add-a, -b, -shelves, test:chooser, test:packs, test:garden-a, -b, -c, -bytes, test:home-a, -b, -c, -asks, test:session-a, -b, -c, -calls and test:text
```

## Home

The app opens on home (`/`, `features/home.contract`): the greeting by the reader's local hour, the Today card (the day's line and its one action: **Start** opens `/today`, **Practice anyway** `/start/<slug>`), a row per list (its title, which opens the list's page, its caption and its verses as plants in order), **Single verses** under the lists (shown only when there is one: each a plant and its reference, with **Remove**), and **Add a list** at the foot with the chooser's limit lines. No icon beside a list's name, no stage glyph and no legend. A plant is a 48-wide button over its drawing, as the current home draws it: a gold dot (`hs.sun`) when the plan holds it open, over a dash in ink once sown and in soil before; pressed, its ground turns `hs.hearing`. A tap on a plant or a single verse opens `/start/<slug>`.

- A list's page (`/lists/:id`, `:id` the slug of the list's id; `features/list.contract`): its title and caption, **Practice this list** with its line, each verse with its stage in words and when it is due, **Move back** on a plant past a seed, and **Remove this list**.
- Removing and moving back ask first, in place: an ask is a state of its row (`homeAsking`, `listAsking`), opened by its button and closed by any other tap; only its Yes acts (`src/home/asks.ts`, `askStep`).
- What home and a list's page draw is `homeRead(offset, wire, mark) with now, seed` and `listRead(slug, offset, wire, mark) with now, seed` (`src/home/sources.ts`): one call reads the garden, takes the session's view (`today.session.wire`, rebuilt as the current app's `SessionView`, `src/home/session.ts`) and answers by the current app's rules (`greetingOf`, `todayOf`, `furrowsOf`, `singlesOf`, `readyOf`, `startOf`, `listCaptionOf`, `listStartOf`, `listLineOf`; `src/home/home.ts`, `src/list/page.ts`). `mark` is the garden's last read in short, so a change asks again. The reads take no queue: Exact's iOS bake refuses a resource that waits on another call, and each write of the file is whole.
- Home stays drawn under a pushed route, so Back finds it where it was, with no row built again.
- The ask lines and the stage words live in the current app's React files, which the port cannot import: `src/home/words.test.ts` holds them to those files' text, and the Contract's ask actions to `askStep`.
- The tests: `src/home/equal-{a,b,c}.test.ts` run 525 generated gardens, session views, instants and zones on the port and on the current app's rules side by side (`src/test/home-model.ts`, `home-check.ts`), with the invariants; `asks.test.ts` walks generated asks over the port's garden, a stored one-verse list, and home's weight. `home.test.contract`, `hslist.test.contract` and `join.test.contract` run live.
- **Add a list** opens Add verses (`/add`, below); what is planted there shows on home after Back.

`bun run exact` first runs `tools/prepare.ts`: it links Exact's standard modules (`@exact/speech-synthesis`, `@exact/speech-recognition`, `@exact/media-capture`) into `node_modules` from the clone, so no machine path is committed, and writes About's licences (`tools/licences.ts`) and the KJV (`tools/kjv.ts`).

## Today

The daily session, one verse at a time (`/today`, and `/start/<slug>` for one verse): the counts, then the item the session shows under its cue, **Hear it** (the system voice reads it, each word lit as the voice reaches it), **Say it** (the recognizer listens on the device, hinted with the verse's words, and Heartseed's matcher marks each word), **Done** (the marks, the matcher's suggestion and the four grades), then **Next** (the try recorded in the garden, and the next item shown) or **Say it again** (the try let go, its help kept). At the end of the run, what grew and the way back home; with nothing planted, the way to add.

- The cue at rest is the current Heartseed's for the verse's stage (`cueIn`), and Show all's cap its `shownAllCap`. `/cue/none`, `/cue/initials` and `/cue/full` show Isaiah 41:10 under that cue, read from the shipped KJV, for the recital's own tests: Next there keeps the try in the launch alone. Under no cue a word is a slot of rules, under first letters its first letter or number as written (the current app's `lettersOf`, `@manna/heartseed/sayit/letters`), under the full text the word.
- At rest a word the cue hides is a button: a tap shows it for `TODAY_PEEK_MS` (the current app's `PEEK_SHOWN_MS`; the contract's `after(1500, …)` is held to it by `src/today/peek.test.ts`) and caps the try at Hard. **Show all** shows every word, caps the try and moves the verse back a stage at Next. Grades above the cap are disabled, and the help line says the cost. The cap is the current Heartseed's `cappedBy`.
- Nothing is recorded before Next: a peek, a Show all or a graded try left unsaid is gone when Today is left or the app closed.
- **Hear it** shows on a new piece at rest with the Voice on (the current app's Listen); Voice Off hides it and refuses `todayHear`. Her and Him read with the system voice the current app's `bestVoice` picks among `speechSynthesisVoices()` (`src/today/reader.ts`, `todayReaderOf`).

- Every rule is `step(state, input)` in `src/today/step.ts`, and the screen is `view(state)` in `src/today/view.ts`. `src/today/sources.ts` holds the state for one launch and answers one data source per input; `features/today.contract` only makes the calls (`speak`, `startSpeechRecognition`, …), forwards each native change as an input naming its utterance or recognition, and draws the view. An input for any other id changes nothing.
- The matcher is the current Heartseed's, imported as `@manna/heartseed/matcher`, whose types are `apps/heartseed/exact/matcher.d.ts`: Exact's type check stages a package's declarations, never its source, and this file imports nothing, so it never reaches `effect`.

## The session

The current Heartseed's own `Session` (`@manna/heartseed/session/service`: `planOf`, the hold, the visit, `startOf`), built once per launch of the data module (`src/session/live.ts`), so its plan lives the launch as in the app and is never derived afresh. What it stands on is reshaped: its `Garden` and `Passages` are the garden file's last read (`readGarden`, which writes nothing), taken at each call; its `Dictation` is Today's recital (listening or not); its store holds the Minutes Settings chose; its clock is the call's. Each command runs through the runner on the call's time and seed, and Today's calls run one at a time.

- A task keyed on the route, its verse, Minutes and Voice sends `todayOpen(route, slug, cue, minutes, voice, now, seed)`: on `/today`, home and `/start/<slug>` the plan is made when first shown with the garden read (`begin`); a Minutes change makes it again (`choose`, keeping an item under recital); `/start/<slug>` (`<slug>` the verse's, as `John-3-16`) starts that verse ahead of the plan once per arrival (`start`); leaving for any screen but the Settings sheet lets the item go (`next`), unless a recital is under way. A plant or a remove that lands makes the plan again (`remake`), as the current app's session does on each change of the passages: `app.ts` takes the garden's `gardenPlant`, `addPlant` and `gardenRemove` through Today's.
- Say it holds the item shown (`hold`); Next hands the try and its help to the garden's own `gardenRecall`, then lets the item go (`next`), and a task refreshes `garden`.
- No own pieces and no taught collections: the plan is over the verses planted alone.

`today.session` is what Today shows of it, and `today.session.wire` the session's view on the wire, for home:

| Field                           | What                                                                                                             |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `mode`                          | `run` (Today, home, a visit), `cued` (`/cue/<cue>`) or `away`                                                    |
| `read`, `planned`               | The garden read; a plan made in this launch                                                                      |
| `nothing`                       | The garden read, nothing planted and nothing shown                                                               |
| `counts`                        | The current app's `countsOf` (`2 to tend · 1 new · about 3 min`); empty before a plan                            |
| `item`, `fresh`, `done`, `held` | An item shown (`shownOf`), a new piece, done in the garden, held by Say it                                       |
| `ended`, `grown`                | The run's end (`tendedOf`) and what grew (`reference`, `slug`, `stage`)                                          |
| `recorded`                      | The recalls Next recorded in this launch                                                                         |
| `wire`                          | `minutes`, `planned`, `items`, `held` (option) and `visit`, each item `reference`, `fresh`, `recalls`, `seconds` |

The session's tests: `src/session/history-{a,b,c}.test.ts` run 300 generated histories on the port and on the current app's services side by side (`src/test/session-history.ts`, `session-model.ts`), over nine zones; `overlap.test.ts` walks every order of two calls' storage answers; `contract.test.ts` holds `session.test.contract`'s literals to the current app's answers.

## Settings, the look and About

The gear in the header (`gear`) opens the Settings sheet (`features/settings.contract`), a modal route of its own (`/settings`), closed by Done (`settings-done`) or the platform's Back: **A day's tending** (the radio group Minutes: 2, 5, 10, 20), **Reads new verses aloud** (Voice: Off, Her, Him), **Appearance** (System, Light, Dark), **Sounds and haptics** (a switch, `settings-feel`, on until turned off, as the hymnal's row; owner, q116), then **About**.

- Each choice is a root `state … persist` holding its text as tapped (`settingsMinutesKept`, `settingsVoiceKept`, `settingsAppearanceKept`, empty until chosen). `src/settings/choices.ts` reads it by the current Heartseed's rule (the text when it is exactly a choice, else 5 minutes, Her and System; `appearanceOf` itself) and offers the current app's lists in their order (`MINUTES`, `CHOICES`, `APPEARANCES`), through the one source `settingsOf`. Sounds and haptics keeps its word, `on` or `off` (`settingsFeelKept`, "on" in a fresh store), read by `src/settings/feel.ts` through `settingsFeelOf` into `settingsFeel`, as the hymnal keeps its own. The session reads `settingsMinutes` and `settingsVoice` (`The session`, above).
- The appearance is the app's scheme: a task keyed on the read appearance calls `setScheme` with it, at a tap and at each launch, on both hosts.
- The look is `app.forma`: every role of the current palette (`@manna/heartseed/theme`) as `hs.<role>` in light and dark, the platform's text roles and grounds drawn in them, the rounded face as `family.hs`. Screens name tokens and roles, never a colour; `src/look/brand.test.ts` holds the file to the palette, every text to AA on its grounds, and the Contract files to no colour literal.
- About (`features/about.contract`, `/settings/about`) is pushed inside the sheet: what Heartseed is, the KJV's note, and `Licences` (`/settings/about/licences`), the licences' texts `tools/licences.ts` writes from the current app's own `readLicence()` to `src/about/licences.ts` (ignored, declared by `licences.d.ts`).
- What a contract test cannot read (a node's computed colour, a radio's checked state, a native relaunch) is in `tools/drive-look.ts`.

## Motion

Calm and quick (owner, q113): every transition 150-250 ms on a soft ease-out, no scale but the 0.97 press, nothing that overshoots, and the current Heartseed's own timings where it has them.

- **Tokens** in `app.forma`: `duration.fade` and `duration.exit` (150 ms), `duration.light` (180 ms, the current Say it's word light), `duration.rise` (250 ms), `duration.ask` (200 ms), `duration.pulse` (1200 ms, the current ring's loop), `easing.out` (`cubic-bezier(0.23, 1, 0.32, 1)`) and `easing.pulse` (the current `Easing.out(Easing.quad)`). Contract names them and writes no time or curve of its own.
- **Reduced motion** is one read, `motionStill` (`features/motion.contract`, `exactViewport().prefersReducedMotion`), handed to each screen as `still`. Every `animation`, `transition`, `-exact-exit-animation` and `-exact-layout-transition` is `(still ? <reduced> : <full>)`, its reduced arm an opacity fade (`hs-fade`, `hs-fade-out`) or `none`; the host's press is left as it runs.
- **What moves:** while Say it listens a ring pulses behind Done (`ring`, mounted only then); the recital's column, keyed by its reference, rises in when Next shows the next verse (`recital`); a word's colour eases as it lights, only while Hear it or Say it runs and never while Settings is up, so a scheme change, the system's or one chosen in Settings, switches the words at once; the run's end brings in its heading, then each grown row 300 ms on and 160 ms apart up to 1200 ms (the first 12, as the current `endMotionOf`), then Back to your field; the inline asks on home and a list's page rise in and leave 4 px up, the rows under them sliding; a plant and a row title press to 0.97.
- The animated nodes write `opacity=1`, their still value, so the driver's `layout` reports their opacity in flight.
- **Ticks** (q114, `features/feel.contract`): a selection tick on a grade chosen, on each setting chosen and on a verse of the chooser ticked or unticked, the hymnal's kind on the same kinds of tap. Every tick is a call of `feelTick`, the app's one `haptic`, which plays only while Settings' Sounds and haptics is on (q116); iOS's System Haptics governs them as well.
- **Held by** `src/look/motion.test.ts` (the tokens, the light and the pulse imported from `@manna/heartseed/sayit/motion`, the run's end's delays against `endMotionOf` from `@manna/heartseed/home/motion`, every row's reduced arm, no motion literal, the press, the 250 ms ceiling and no overshoot for every token a row names, of any family, and every token of the brand, the ticks and their one gate) and, live, `tools/drive-motion.ts web|ios` (`pulse`, `words`, `scheme`, `home` and `ending` as its second argument run those alone; iOS films each moment into `.exact/shots/`).
- An exit leaves the tree at once: the driver lists no node that is leaving, so a test reads an ask gone right after Keep, with no `clock settle`. The screen still draws it while it leaves: `drive-motion web home` reads its frame's pixels 60 ms after Keep (still drawn) and once its exit and the slide under it are done (as settled).

## Add verses and the chooser

**Add verses** (`/add`, `features/add.contract`) is the current Heartseed's shelves in its order (`SHELVES`), as the platform's grouped list: **Any passage** (the chooser), then every other shelf (the picks, the promises, each section of Haskell's Bible Handbook) a head that opens in place, one at a time, as the current sheet's shelves do (`addShelf`), so only the open shelf's rows are answered and drawn. A row is a list's title, its count and what it offers now (`offerStateOf` over the field home draws): `Plant`, `In your field`, or nothing at a limit; the foot says the lists' limit while three are held, else the single verses' at twenty. A row opens its list (`/add/lists/:list`): its verses with their words, and **Plant** while it offers one; a refused plant says the current sheet's line in place. Once a plant lands the reader is back at Add verses.

- What each screen draws is `src/add/shelves.ts` over the garden one call reads: `addRead(open, mark)` and `addList(slug, answer, mark)`, each `with now, seed` (`src/add/sources.ts`), outside the garden's queue as home's reads are. Add verses answers titles and references alone (under 60 KB, no verse's words); a list's page carries its words (`versesOf`).
- **Plant** is the garden's `addPlant(slug, now, offset, seed)`, through its queue (`src/garden/sources.ts`): what the current sheet runs for the row's source (`src/garden/program.ts`, `plantList`): a pick of one or two verses joins each to the single verses (`plantsSingly`), a passage of three or more is added as a list, a Handbook list is planted by its id. It answers `Planted`, `Already`, `Full`, `Short`, `Unread`, `Failed` or `Invalid` (no such row).
- **The chooser** (`features/chooser.contract`, `src/chooser/`): the books under their testaments (`/add/bible`), a book's chapters (`/add/bible/:book`), and a chapter's verses with their words (`/add/bible/:book/:chapter`, `textOf`). A tap is `chooserTap`, one step of the current app's `tapVerse` (a second tap ends a range, clipped to 20; a tap on the one verse chosen clears it); `chooserRead` (given the single verses held, their references joined by `|`) says what the footer offers: the range and its count, the cap, **Plant** at 3 verses or more, `SHORT_LINE` under 3 with **Add to single verses** (the owner's rule, beyond the current chooser: one or two verses join the single verses, as a shelf's short pick does) as `Passages.join` judges it: offered while a verse of the range is not single yet and the single verses have room for those verses, their limit line when they have none, neither once every verse is single; and the line a plant's answer leaves. Plant is the garden's `gardenPlant`, Add to single verses its `gardenJoin` (`Passages.join`); each makes Today's plan again once it lands.
- The tests: `src/chooser/chooser.property.test.ts` steps and reads the chooser against `tapVerse` and the current footer over one chapter of every length; `src/add/shelves.test.ts` holds the shelves to `SHELVES` and every row's offer to `offerStateOf` over generated gardens; `src/add/plant-{a,b}.test.ts` run 40 generated histories of chooser ranges, shelf rows, Handbook lists, removes and relaunches on the port and on the current app's `Passages` over `KeyValueStore.layerMemory` (`src/test/add-history.ts`), with the bytes and the invariants; `words.test.ts` holds the words and the answers' sizes; `today.test.ts` the plan made again after a shelf's plant. `add.test.contract`, `chooser.test.contract` and `tools/drive-add.ts` run live.
- `@manna/core/bible`'s books reach Exact's type check through `src/chooser/decl/bible.d.ts` (`tsconfig.json`'s `paths`), held to the source by `src/chooser/declared.test.ts`.

## The garden and Your verses

What is planted (lists of three verses or more, and single verses), each verse's plant, stage, FSRS schedule and history, kept across launches in `app:/data/heartseed.json`. **Your verses** (`/verses`, reached by its route and by Today's way to add) lists them, with **Add verses**; a driver's launch also plants three verses of John 3 (16-18, then the next three), a verse of Psalm 119 or Psalm 23:1-2 (two verses: refused as a list), and removes a list or a single verse.

- The current Heartseed's own services do the work, imported (`@manna/heartseed/garden`, `passages`, `lists`, `sayit`, `day`, `fsrs`, `chooser`; their declarations are `apps/heartseed/exact/*.d.ts`, held to the sources by `apps/heartseed/scripts/exact-declared.test.ts`). Each source is one call through the runner (`src/garden/program.ts` → `runCall`): it builds `Garden`, `Passages` and the single verses over `@manna/exact-kit/storage`'s `KeyValueStore` on the file, makes its one change and answers what they hold after it. The stored keys and bytes are the current app's, so `ex-hs-import` copies keys.
- Calls run one at a time (`src/garden/writes.ts`), reads too: each call builds its own store, so the current app's `Semaphore` orders nothing across calls. A recall's step back and the recall itself reach the file in one write (`program.ts`, `stagedOf`): when it fails, the call answers `Failed` with the file as it was, so no call reads one without the other (`src/garden/recall.test.ts`). The protocol, a write that may fail included, is `src/garden/writes.qnt`, walked whole in `writes.test.ts`; `test:slow` type-checks it (`quint typecheck`). Check the model itself by hand: `quint run --invariant=safe --max-steps=12 src/garden/writes.qnt` answers `[ok] No violation found`; with `STAGED` false it answers `[violation]` (a recall's second write fails and the next call reads the half), and with `owner == -1` taken out of its `read` (no queue) a read between the other call's two writes.
- Single verses are the current app's `Passages` too (`join` and `part`, `heartseed/singles`, at most `MOST_SINGLES`): one verse joins them, any other range is added as a list, and `add` answers `Short` under `LEAST_VERSES`, with the chooser's `SHORT_LINE` and `SINGLES_LIMIT_LINE` shown. A stored one-verse list moves to the single verses when `Passages` is read (its `migrated`).
- `virtual:heartseed-kjv`, which the current app's lists read, is the whole KJV (`The text`, below).
- A driver's launch (`HEARTSEED_GARDEN_DRIVE` set, `app.json`'s `env`) adds the plant buttons and test controls under each verse (Good, Good after a peek, Good after Show all, Move back); a plain launch has none, and plants only through Add verses. `tools/drive-garden.ts web|ios` drives them; `tools/drive-add.ts` reads a plain launch's tree.

The seam other units call, every source taking the call's time, zone and seed from `exactTime()` (`time.epochAtZero + performanceNow()`, `time.utcOffset`, `time.seed`):

| Source         | Arguments                                                              | Answers                                                                                                                                                                      |
| -------------- | ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `gardenRead`   | `offset` `with` `now`, `seed`                                          | `GardenShown`: `read` (false while the store is unread, which claims nothing), `lists` (`id`, `slug`, `title`, `verses`), `singles`, `listsFull`, `singlesFull`, `limitLine` |
| `gardenPlant`  | `book`, `chapter`, `first`, `last`, `now`, `offset`, `seed`            | `GardenChange`: `answer` `Planted`, `Already`, `Short` (two verses), `Full`, `Invalid`, `Unread` or `Failed`; `line` (the Short line, else empty)                            |
| `gardenJoin`   | `book`, `chapter`, `first`, `last`, `now`, `offset`, `seed`            | `GardenChange`: each verse of the range joined to the single verses (the chooser's offer under 3): `Planted`, `Already`, `Full`, `Invalid`, `Unread` or `Failed`             |
| `addPlant`     | `slug` (a shelf row's), `now`, `offset`, `seed`                        | `GardenChange`: as `gardenPlant`, by the row's source (Add verses, above); `Invalid` for no such row                                                                         |
| `gardenRemove` | `id` (a list's, or `single:<reference>`), `now`, `offset`, `seed`      | `GardenChange`: `Removed`, `Absent`, `Unread` or `Failed`                                                                                                                    |
| `gardenRecall` | `reference`, `GardenRecallIn`, `GardenHelpIn`, `now`, `offset`, `seed` | `GardenVerseChange`: `answer` `Kept`, `Unread`, `Failed` or `Invalid` (arguments that do not decode), and the verse after it                                                 |
| `gardenBack`   | `reference`, `now`, `offset`, `seed`                                   | `GardenVerseChange`: `Moved`, `Failed` and the verse after it                                                                                                                |

A `GardenVerse` is `reference`, `slug` (its nodes' names: `plant-`, `stage-`, `due-`, `single-<slug>`), `planted`, `stage`, `recalls`, `lastGrade`, `due`, `dueNow` and `dueIn` (reader's days from today, the day turning at 04:00 in the call's zone). `GardenRecallIn` is SayIt's recall (`startedAt`, `offset`, `grade`, `suggested`, `words`, `missed`, `peeked`, `extra`); `GardenHelpIn` is SayIt's help (`peeked` word indexes, `shownAt` (none for no Show all), `cap`). A recall's grade is held to the help's cap, the cap no better than Hard after a peek and than `shownAllCap` after Show all, whose step back is kept first, at its instant. Every change `refreshes` `garden`.

## The text

Any verse's words, for the screens that need words and nothing else (`src/text/`):

| Source       | Arguments                          | Answers                                                                                                                                                                  |
| ------------ | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `textVerses` | `book`, `chapter`                  | The chapter's verses, each its shown text in order; none for a chapter the canon lacks                                                                                   |
| `textOf`     | `book`, `chapter`, `first`, `last` | `TextPassage`: `reference` as the canon writes it, and `verses` (`verse`, `text`); a range past its chapter's end stops there, and a malformed one holds none under `''` |

Both read the current Heartseed's `versesOf` (`@manna/heartseed/kjv`, declared by `apps/heartseed/exact/kjv.d.ts`) over the import it reads, `virtual:heartseed-kjv`, so every current-app module over it (`passages`, `lists`) runs unchanged here. That import is `src/text/kjv.gen.json` (`tsconfig.json`'s `paths`): the canon's 1,189 chapters, each one string of its verses, derived by the current app's own deriver (`@manna/heartseed/vite/kjv`) and written by `tools/kjv.ts` from `tools/prepare.ts` only when its text changes (ignored, never committed). It ships as a module the data module imports, and a read splits only the chapter it asks for; the Bun tests get the same corpus through `tools/setup.ts`, behind a counter of the chapters read.

`features/text.contract` draws nothing: its resources are the probe `text.test.contract` reads, John 3:16, Psalm 119:176 and Revelation 22:21 by fingerprint (`textSum`: each verse's length and FNV-1a sum, `src/text/sum.ts`), held to the current app's words by `src/text/contract.test.ts`, so no verse's text is written in a test. `bun run test:text` runs the text's Bun tests.

## The downloads

The reader's packs are downloaded once and kept on the phone, not bundled (owner, q123: "let it be downloaded"; q126: "Download them too"). One downloader, `src/packs/`, serves every pack: Ellen White's Bible Commentary first (`src/commentary/`, `GET /api/commentary/pack` on egw.cvr.im, `apps/egw-search`), and the study packs (cross-references, Strong's, the word index) as `hs-study-packs` adds them. No commentary's text is in the repository or the app's bundle.

- **A pack** is a `PackSpec` (`src/packs/spec.ts`): its `name`, its `path` on the base, its `file` in `app:/data` (which `app.ts` grants `fs.read` and `fs.write`), its words (`title` in the status line, `noun` once it lands, `waiting` for its own feature) and its `check`. `packSources({ setting, packs: [COMMENTARY, …] })` in `app.ts` takes the list; a pack's reader reads it through `packOf(spec, mark, storage)`. Each body is versioned by its content (`<count>-<sum as 8 hex digits>`, its `version` among the fields before its body), and answers `304` for `If-None-Match` its version.
- **When.** `packsFetch` is the Read tab's first showing in a launch, in the background, and asks every pack at once: each fetches when it is not kept, its last try failed, or its last good check is more than 7 days away; `packsRetry` is Try again, which fetches every pack not already out. Asks at once share each pack's one fetch out. The ask answers once every pack has settled.
- **How.** One `fetch` per pack of `base + path` naming its kept version in `If-None-Match`. A `304` keeps the check's time. A `200` is checked whole by the pack's `check` (the commentary's `checkPack`: it parses, `format` is 1, `count` is the notes', every index is inside the notes, the FNV sum of `src/text/sum.ts` over the notes is `sum`, `version` is `<count>-<sum as 8 hex digits>`), written to its file in one `atomicWriteFile`, and only then is its version kept. Anything else keeps what was there, and one pack's failure keeps no other from landing. Contract persists every pack's version and check time as one string, `packsKept`, a line `<name> <version> <checkedAt>` per pack (`keptWith`, `keptIn`). A launch takes what is kept from each file's own head at its first ask (`keptOf`), so a relaunch between the write and the version names the file it has and asks again.
- **What the reader sees.** One status for every pack (`packsShown`, a `PacksState`): `phase` `none`, `fetching`, `ready` (every pack kept) or `failed`; `missing`; `foot`, the one quiet line `PacksLine` draws at a chapter's foot ("Getting Ellen White's commentary…" while it is on its way, every missing pack's title listed, "Commentary is on this phone now." for 3 seconds once packs first land, held to `after(3000, …)`); `retry`, whether Try again shows. Each pack's feature reads its own state through `packView(name, …)`: the commentary's is `commentaryShown` (a `PackState`: `phase`, `version`, the reader's `mark`, `line`, what the study sheet's Commentary tab says while it is missing, and `retry`). With every pack kept an update, or a failed one, shows nothing.
- **Reading the commentary.** `commentaryRead(book, chapter, mark)` and `commentaryCounts(book, chapter, mark)` answer a chapter's notes and counts (`have` false with no pack), reading the kept file once per launch and `mark` (the kept version); a pack a fetch just wrote is held parsed and never read again.
- **Where they come from.** egw.cvr.im on a plain launch (`net.fetch https://egw.cvr.im`). A driver's launch names a loopback fixture in `HEARTSEED_PACKS_BASE` (app.json's `env`), on its checkout's own port; a development build's `development net.fetch http:` grant admits it, and a production bake leaves that line out. A fixture launch also draws `PacksProbe` on Your verses (Fetch, Try again, the line) until the Read tab calls `packsFetch`.
- **The rules** are `src/packs/`: `step.ts` (one pack's protocol as one pure `step` with the pack's check, and the persisted string), `shown.ts` (the status and each pack's state, and their words), `spec.ts` (a pack, and the version at a file's head), `sources.ts` (one launch's machines, the fetches and the files). `step.test.ts` runs 300 generated histories (the tab shown, Try again, days passing, `200`, `304`, `500`, a refusal, a body cut short, a character changed, a wrong format, an index out of range, a write that fails, a relaunch, stray answers) against a reference model, and every order of a small alphabet six deep, over the commentary's pack; `sources.test.ts` the sources over a stand-in server with the commentary and a made-up second pack (offline at the first launch, a partial download, one pack failing while the other lands, a corrupt pack, an update), each call started inside `withDataHost`; `src/commentary/pack.test.ts` the commentary's checks and reader over generated made-up packs, and `sumOf`'s shared vector with `hs-bc-api`. `bun run test:packs` runs them.
- **The interleaving.** `src/packs/packs.qnt`: one pack (each has its own file, machine and line), two launches over one storage, a write that may fail, a relaunch anywhere; "the file is whole and its version never ahead of it". `quint run --invariant=safe --max-steps=12 src/packs/packs.qnt` answers `[ok] No violation found`; with `ATOMIC` false it answers `[violation]`. `test:slow` type-checks it.
- **Live.** `commentary.test.contract` holds a plain launch (egw.cvr.im, no probe, the line before any fetch). `tools/drive-commentary.ts web|ios` runs the rest against `tools/commentary-fixture.ts` (two made-up commentary packs, a `304` for its `ETag`, a `500`, a body cut short or with a changed character, a held answer, stopped for a refusal).

## Where a feature's files go

| Path                       | What                                                                                                    |
| -------------------------- | ------------------------------------------------------------------------------------------------------- |
| `app.contract`             | The root view: per feature one `use` line, one `members` line, one route and one branch of the stack    |
| `app.ts`                   | The data module: per feature one spread of its sources into `sources`, and its grants                   |
| `features/<name>.contract` | A feature's members of the root (`members HeartseedExact`: its states, resources, calls) and its screen |
| `src/<name>/**`            | A feature's logic: pure TypeScript, imported by `app.ts`, tested in Bun                                 |
| `<name>.test.contract`     | A feature's contract tests, beside `app.contract`: `exact test` and `verify` read only those            |
| `app.test.contract`        | The app's own test: its name heads the first screen                                                     |
| `tools/`                   | Host scripts: `prepare.ts`, and drives a `.test.contract` cannot hold                                   |
| `strings/en.json`          | The purpose strings of the app's grants                                                                 |
| `app.forma`                | The brand: the current palette's roles as tokens, the platform's roles drawn in them, the rounded face  |
| `exact.mjs`                | The kit's launcher, for Exact's own `bun exact.mjs` calls; `bun run exact` is `manna-exact`             |

A feature's names start with its own (`today…`), since its members share the root's one namespace. Logic of the current Heartseed is imported through its package's exports, never copied: `src/no-copy.test.ts` fails on a copy. A Bun test of a module `app.ts` imports runs it under `withDataHost` (`@manna/exact-kit/data-host/testing`) to fail where Hermes would, as `src/app.test.ts` does.

`app.contract.d.ts` (the types `app.ts` imports), `src/about/licences.ts`, `.exact/` (builds, screenshots, scratch) and `dist/` are generated and ignored. `app.ts` stays out of the typecheck, which covers `src/` alone: a test reaches `answer` through `src/test/app.js`, whose types are `app.d.ts` beside it, so a fresh checkout type-checks with no generated file. `src/about/licences.d.ts` names its writer (`@writer`), which the gate's env-pass requires before it counts the declaration for the absent module.
